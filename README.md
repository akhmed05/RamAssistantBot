# RAM AI / RamAssistantBot

Read-only MVP виртуальной команды для двух кабинетов Wildberries. Использует
существующий Telegram-бот. Архитектура, аудит исходного кода и этапы внедрения:
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Что действительно работает

- `/start` сохраняет старые четыре кнопки и добавляет «🤖 RAM AI»; `/ram` открывает
  выбор кабинета, продажи, остатки, агентов, статус, журнал и помощь.
- `/task продажи` и `/task остатки`: главный агент закрепляет выбранный кабинет,
  вызывает официальный Statistics API WB, аналитик строит сводку, контролёр
  проверяет формат. Не требуется OpenAI. Чтение продаж за 7 суток, остатков WB
  (не FBS), отдельные ключи и права каждого кабинета.
- Авторизация по Telegram user ID, только личные чаты. При пустом
  `RAM_OWNER_IDS` доступ закрыт ко всем функциям, включая прежние.
- SQLite: выбор кабинета, журнал, состояния задач, защита от повторной обработки
  одного callback/message, лимиты и кэш. Сырые WB-строки, промпты и секреты не
  сохраняются. Сводки WB содержат бизнес-данные — защитите volume и резервные копии.
- Предварительное резервирование дневного бюджета запросов/токенов OpenAI,
  ограничение длины ввода/вывода, без автоповторов платных запросов.
- `OPENAI_MODEL` заменяет жёстко заданный `gpt-4`. Если модель не задана, AI
  не вызывается. 404 показывает понятную диагностику без сырого тела ошибки.
  Модель не подменяется автоматически; доступность определяется вашим проектом.

Карточки, реклама, контент и финансы ещё НЕ интегрированы: кнопки создают только
черновик общего плана. Согласование/отклонение черновика владельцем действует
15 минут, одноразовое и привязано к исходному кабинету. Согласование не отправляет
изменения WB. Инструментов записи вообще нет. CTR, ДРР, прибыль, unit economics,
создание картинок и автоматическая оптимизация не заявляются как работающие.
Главный агент в MVP — детерминированный маршрутизатор, свободное LLM-планирование
отложено. Контролёр — набор правил, а не отдельная LLM.

## Установка и тесты

Python 3.11 (для aiogram 2 / aiohttp<3.9):

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r RamAssistantBot/requirements.txt
.venv/bin/python -m pip check
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m unittest discover -s tests -v
```

Тесты блокируют socket connect/getaddrinfo, не запускают polling. Реальные SDK
OpenAI и HTTP WB проверяются через `httpx.MockTransport`; Telegram маршрутизация
проверяется искусственными updates. Это не подтверждает живую авторизацию API.
В подготовленной среде Python: `/workspace/.venvs/ramassistant/bin/python`.

OpenAI SDK 1.3.7 и httpx 0.27.2 сохраняются совместимой парой: httpx 0.28 удалил
`proxies`. Выберите доступную вашему проекту chat-completions модель, принимающую
`max_tokens`; reasoning-модели с другими параметрами в этом MVP не поддерживаются.

## Переменные окружения

Только Railway Variables/секреты среды. Не присылайте ключи в Telegram, чат,
issues или PR. `.env.example` содержит пустые ключи; `.env` автоматически не читается.

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Telegram bot token |
| `RAM_OWNER_IDS` | Telegram user ID владельцев через запятую; не username/chat ID группы |
| `RAM_WB_1_STATISTICS_TOKEN`, `RAM_WB_2_STATISTICS_TOKEN` | Два отдельных токена WB категории «Статистика», желательно read-only |
| `RAM_WB_1_READ_SCOPES`, `RAM_WB_2_READ_SCOPES` | Разрешённые инструменты: `sales,stocks`, `sales` или `stocks`; пустое = запрет |
| `RAM_WB_1_NAME`, `RAM_WB_2_NAME` | Названия кабинетов без секретных данных |
| `RAM_DB_PATH` | Для Railway volume: `/data/ram_ai.sqlite3`; локально по умолчанию `data/ram_ai.sqlite3` |
| `OPENAI_API_KEY` | OpenAI key (не нужен для чтения WB) |
| `RAM_OPENAI_API_KEY` | Альтернативное имя; `OPENAI_API_KEY` имеет приоритет |
| `OPENAI_MODEL` | Обязательное для AI имя модели с доступом в вашем проекте; по умолчанию пусто |
| `OPENAI_MAX_TOKENS` | Максимум вывода, 800 по умолчанию, допустимо 1–4096 |
| `RAM_AI_DAILY_REQUESTS` | Общий максимум AI-запросов в сутки UTC, 30 |
| `RAM_AI_DAILY_TOKEN_BUDGET` | Общий резерв токенов в сутки UTC, 60000 |
| `RAM_WB_DAILY_REQUESTS` | WB-запросы на каждый кабинет в сутки UTC, 200 |
| `GOOGLE_SCRIPT_URL` | Необязательная замена прежнего Apps Script URL |
| `BOT_PROXY` | Необязательный Telegram proxy; fallback `HTTPS_PROXY` |

Для AI резервируется верхняя оценка: UTF-8 байты ввода + 256 overhead + максимум
вывода. Ошибки также расходуют резерв, автоматического возврата нет. Это лимит
запросов и токенов, НЕ гарантированный рублёвый/долларовый потолок: цена зависит
от выбранной модели. Настройте дополнительно бюджет проекта OpenAI у провайдера.

## Ограничения официального API WB

Жёсткий allowlist, только GET:

- `https://statistics-api.wildberries.ru/api/v1/supplier/sales`
- `https://statistics-api.wildberries.ru/api/v1/supplier/stocks`

Токен передаётся в `Authorization`, редиректы запрещены. Для каждой пары
кабинет/endpoint интервал не менее 65 секунд, кэш 65 секунд, 429 учитывает
числовой `Retry-After` (до суток). 401/403 требуют проверки категории и прав
токена, 404 — актуальности endpoint; тела ошибок не показываются и не логируются.
Точные категории, актуальные лимиты/платный доступ проверьте перед staging-запуском
на [портале разработчиков WB](https://dev.wildberries.ru/).

`dateFrom` продаж — время изменения записи, а не продажи; сводка дополнительно
фильтрует поле `date`, даты без offset трактуются как Москва UTC+3. Возвраты
определяются по saleID R, знак суммы применяется аналитиком. «К перечислению»
не является прибылью. Оперативные данные WB обновляются с задержкой и могут
уточняться. Большие ответы (>=60000 строк, консервативный порог) явно помечаются
как потенциально неполные: курсорная догрузка пока не реализована. Остатки
относятся к складам WB, это не FBS и не учёт остатков в реальном времени.

## Railway: отдельный staging, без изменения production

1. Просмотрите PR. Создайте отдельный Railway service/environment с веткой
   `feat/ram-ai-readonly-mvp` и отдельным тестовым Telegram-ботом.
   Не используйте production BOT_TOKEN: два polling-процесса конфликтуют.
2. Root Directory `/RamAssistantBot`, Python `3.11.17` из `.python-version`,
   install `pip install -r requirements.txt`, start `python main.py`, replicas `1`.
   HTTP healthcheck/публичный домен не нужны (polling).
3. Подключите постоянный volume `/data`, `RAM_DB_PATH=/data/ram_ai.sqlite3`.
   Без volume после redeploy пропадут журнал, dedup и лимиты. Multi-replica и
   blue-green polling с одним токеном не поддерживаются.
4. Задайте owner ID, два Statistics token и разрешения чтения в Railway Variables.
   OpenAI key/model добавьте только если нужны ответы AI.
5. Доступ исходящих HTTPS: `api.telegram.org`, `statistics-api.wildberries.ru`,
   `api.openai.com` (AI), `script.google.com`, `script.googleusercontent.com` (заявки).
6. Staging-проверка: /start → /ram → кабинет 1 → продажи/остатки → кабинет 2 →
   продажи/остатки. Сверьте значения с каждым кабинетом, статус, журнал, отказ
   постороннему user ID, черновик → отклонение/согласование без изменений WB.
   Для AI: задайте проверенную модель, отправьте один вопрос; 404 не считать исправленным
   в production, пока ответ не получен с ключом владельца.
7. Проверьте сохранение журнала и лимитов после redeploy staging. Только после
   приёмки владелец решает о merge и отдельном production deploy. Этот PR ничего
   не развёртывает и не меняет Railway Variables.

Polling теперь `skip_updates=False`: накопленные updates обрабатываются; повтор
одного ID защищён SQLite. После аварии job `running` не переисполняется автоматически;
проверьте журнал и создайте новое задание. Для read-only действий это безопасно.
Журнал пока не имеет автоочистки: архивируйте volume с учётом бизнес-данных.

## Сохранённые прежние функции

AI-вопросы, заявки Apps Script и PDF сохраняются (теперь только владельцы).
YouTube-саммари остаётся исходной явно указанной заглушкой без транскрипции;
`media/info.pdf` — исходный некорректный файл 20 байт. Их не следует демонстрировать
как готовые интеграции. Реальная работа Apps Script и полноценность PDF не
подтверждены этим PR. Новые WB ответы не используют фиктивные данные.
